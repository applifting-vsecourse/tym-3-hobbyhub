# ADR-0012: Rozsah datového modelu vůči MVP

**Status:** Navrženo ❓ <br>
**Datum:** 11-10-2026 <br>
**Autor:** Marek

## Kontext

Feature breakdown v0.4 přesunul 36 featur z MVP do Nice to have nebo Mimo rozsah. Mezi nimi jsou celé skupiny (E7), náhradníci, docházka, hodnocení, nástěnka, topování, storno lhůty, schvalovací režimy, blokování uživatelů a skóre spolehlivosti. Model je pokrýval všechny, takže je výrazně širší než MVP.

Sitemapa v0.3 rozlišuje rozsah barvou: MVP, MVP navržené dodavatelem, Nice to have, Mimo rozsah.

## Rozhodnutí

- Model obsahuje MVP i Nice to have. Nice to have prvky se odliší barvou v diagramu a poznámkou „Nice to have, F-x.y“.
- Prvky mimo rozsah v modelu také zůstávají pro případ, že se rozsah změní, s poznámkou „Mimo rozsah, F-x.y“:
  - `User./organizerReliabilityScore` (F-10.6);
  - `Poll`, `PollOption`, `Reaction`, `ReactionType` (F-05.13: ankety a reakce „později případně“).

## Zvažované možnosti

- **A: Model jen pro MVP**
  - Výhody: přesně odpovídá aktuální dodávce.
  - Nevýhody: zahodí se hotová práce; při rozšíření se model navrhuje znovu.
- **B: MVP a Nice to have odlišené, mimo rozsah smazat**
  - Výhody: model nedrží nic, co se nebude dělat.
  - Nevýhody: rozsah se během projektu už jednou měnil.
- **C: Ponechat vše a odlišit rozsah (zvoleno)**
  - Výhody: změna rozsahu je jen změna označení; model zůstává úplný.
  - Nevýhody: diagram je větší a čtenář musí sledovat označení.

## Důsledky

- Z diagramu musí být vždy poznat, co je MVP.
- Při další verzi breakdownu stačí projít označení, model se mění jen u nových požadavků.
- Týká se i ADR-0004 až ADR-0007, které jsou celé nebo zčásti Nice to have.
