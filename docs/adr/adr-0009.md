# ADR-0009: Obsazenost akce a místa mimo aplikaci

**Status:** Navrženo ❓ <br>
**Datum:** 11-10-2026 <br>
**Autor:** Marek

## Kontext

Z feature breakdownu v0.4:

- Organizátor při vytvoření akce zadá již obsazená místa (F-05.1). U existující party lze evidovat obsazená místa a hledat zbývající kapacitu (F-05.2).
- Organizátor eviduje **počet** účastníků své party mimo aplikaci, bez jejich účtů. Obsazenost = tato místa + schválení uživatelé. Počítadlo chybějících do minima, volných do maxima a stav pod minimem / naplněno / plno. Schválení ani úprava externích míst nesmí překročit maximum (F-05.6).
- Kapacitu nelze snížit pod počet obsazených míst (F-05.10). Při plné kapacitě se nové žádosti nepřijímají (F-06.1).
- Statistiky účastníků (medián věku, poměr pohlaví) se počítají jen ze schválených registrovaných, od 3 lidí, s uvedením, kolik z obsazenosti pokrývají (F-06.7).
- Metriky mají oddělit již obsazená místa od nových účastníků. Zda se akce uskutečnila, se ověří ruční zpětnou vazbou organizátora (F-11.6).

Model dosud měl dvě konkurenční řešení: ručně přidané hosty jménem (`Participation.guestName`, podle F-05.6 ve v0.2) a počet zveřejněných míst (`Event.publicSpots`). Ani jedno neodpovídá v0.4.

## Rozhodnutí

```
Event
- externalOccupiedSpots: Integer = 0       // místa obsazená mimo aplikaci
- /approvedCount: Integer                  // účasti ve stavu APPROVED
- /occupiedSpots = externalOccupiedSpots + /approvedCount
- /missingToMinimum = max(0, minParticipants − /occupiedSpots)
- /freeSpots = maxParticipants − /occupiedSpots
- /fillState: FillState
+ getParticipantStats(): ParticipantStats
+ confirmHeld(held: Boolean)

«enumeration» FillState: BELOW_MINIMUM, MINIMUM_REACHED, FULL

«dataType» ParticipantStats
- medianAge: Integer
- maleShare: Decimal
- femaleShare: Decimal
- includedCount: Integer     // schválení registrovaní, ze kterých se počítá
- occupiedCount: Integer     // celková obsazenost, pro uvedení pokrytí
```

- `Participation.guestName` a `Event.publicSpots` se mažou. Každá účast má uživatele (`user [1]`).
- Omezení: `{externalOccupiedSpots ≥ 0}`, `{/occupiedSpots ≤ maxParticipants}`, `{getParticipantStats jen při /approvedCount ≥ 3}`.
- `confirmHeld` nastaví po akci stav `FINISHED` (akce proběhla), nebo `NOT_HELD` (neproběhla) podle zpětné vazby organizátora (F-11.6). Dřívější omezení `NOT_HELD ⇒ /approvedCount < minParticipants` vycházelo z F-10.6, který je mimo rozsah, a maže se.

## Zvažované možnosti

- **A: Jmenovití hosté (`guestName`)**
  - Výhody: organizátor vidí jména.
  - Nevýhody: v0.4 to nechce („bez nutnosti jejich účtů“, jen počet); zbytečná práce pro organizátora; hosté by bez data narození zkreslovali statistiky.
- **B: Počet zveřejněných míst (`publicSpots`)**
  - Výhody: přímo říká, kolik lidí se hledá.
  - Nevýhody: obsazenost by se musela dopočítávat obráceně; F-05.6 a F-11.6 mluví o obsazených místech.
- **C: Počet míst obsazených mimo aplikaci (zvoleno)**
  - Výhody: přesně podle F-05.6; jedna hodnota; metriky snadno oddělí externí místa od nových účastníků (F-11.6).
  - Nevýhody: organizátor musí počet udržovat aktuální sám.

## Důsledky

- Pin na mapě (F-02.2), karta (F-02.3) i detail (F-02.4) čtou `/missingToMinimum`, `/freeSpots` a `/fillState`.
- Pozvánky a pořadník (ADR-0004, Nice to have) od `/freeSpots` navíc odečítají držená místa.
- Organizátor, který se do akce přidá sám (ADR-0005), se počítá do `/approvedCount`.
