# ADR-0008: Společná nadtřída Request pro žádosti

**Status:** Navrženo ❓ <br>
**Datum:** 11-10-2026 <br>
**Autor:** Marek

## Kontext

Model má dvě žádosti:

- žádost o účast na akci: zpráva organizátorovi, ruční schválení nebo zamítnutí s důvodem, zrušení čekající žádosti (F-06.1, F-05.7, F-08.1);
- žádost o členství ve skupině: zpráva, schválení nebo zamítnutí s důvodem, zrušení čekající žádosti, přehled se stavy čeká / schváleno / zamítnuto (F-07.3, F-07.7, Nice to have).

Obě mají stejný životní cyklus, stejné atributy i stejné operace. Liší se jen tím, k čemu se vztahují (akce, nebo skupina).

## Rozhodnutí

Společné atributy a operace budou v abstraktní nadtřídě `Request`, ze které dědí `ParticipationRequest` a `MembershipRequest`.

```
«abstract» Request
- status: RequestStatus
- message: String [0..1]          // F-08.1
- requestedAt: DateTime
- decidedAt: DateTime [0..1]
- rejectionReason: String [0..1]
+ approve()
+ reject()

«enumeration» RequestStatus: PENDING, APPROVED, REJECTED, WITHDRAWN, CLOSED

ParticipationRequest --|> Request     Event ◆ "0..*" ParticipationRequest
MembershipRequest    --|> Request     Group ◆ "0..*" MembershipRequest
```

- Vazba na žadatele (`user → User [1]`) zůstává v podtřídách. Přesouvat asociaci do nadtřídy by v Modeliu znamenalo vazby znovu vytvořit a nic by to nepřineslo.
- `WITHDRAWN`: žadatel čekající žádost zrušil (F-06.1, F-07.7).
- `CLOSED`: žádost uzavřená bez rozhodnutí, protože akce byla zrušena (F-05.7). U skupiny se zatím nepoužívá.

## Zvažované možnosti

- **A: Dvě nezávislé třídy**
  - Výhody: žádná dědičnost.
  - Nevýhody: atributy, operace i omezení se opakují; změna jedné žádosti se snadno zapomene u druhé.
- **B: Abstraktní nadtřída `Request` (zvoleno)**
  - Výhody: společný životní cyklus a omezení na jednom místě; sdílený výčet stavů.
  - Nevýhody: `CLOSED` je ve sdíleném výčtu, i když ho používá jen žádost o účast.

## Důsledky

- Omezení společná pro obě žádosti (`decidedAt` je vyplněn ⇔ status ≠ PENDING, `rejectionReason` jen při REJECTED) patří k `Request`.
- Navazuje na ADR-0003 (oddělení žádosti a účasti).
