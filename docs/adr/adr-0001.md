# ADR-0001: Modelování místa akce jako value objektu Location

**Status:** Přijato ✅<br>
**Datum:** 10-10-2026 <br>
**Rozhodující:** Marek

## Kontext
Při tvorbě datového modelu (diagramu tříd) HobbyHubu potřebujeme určit, jak u Akce (`Event`) uložit místo konání. Na místo působí několik požadavků z feature breakdownu.

* Organizátor zadává místo přes našeptávač adresy a pin v mapě a určuje typ místa, tedy veřejné nebo soukromé prostory (F-05.1).
* Akce se zobrazují v mapě s piny a jejich shlukováním, výchozí výřez je v okolí uživatele (F-02.2). Potřebujeme proto znát souřadnice.
* Karta akce v seznamu ukazuje akce nejbližší uživateli (F-02.3) a metriky se filtrují podle města (F-11.6). Potřebujeme proto strukturované části adresy, ne jen jeden řetězec.
* Přesná adresa soukromých prostor je skrytá do schválení účastníka (F-02.4, F-06.5, F-10.4).
* Mapový podklad a geokódování zajistí externí služba, např. Mapy.com API nebo OpenStreetMap (F-12.3).

Adresa a souřadnice spolu musí zůstat konzistentní a nechceme po organizátorovi, aby je zadával dvakrát.

## Rozhodnutí
Budeme místo akce modelovat jako samostatný typ **Location**, který Akce obsahuje kompozicí 1:1 (přes atribut `location: Location`). Location nemá vlastní identitu, je neměnný a při změně místa se nahradí celý.

```
Event
- location: Location

Location
- street: String
- city: String
- postalCode: String
- country: String
- latitude: Decimal
- longitude: Decimal
- placeName: String // např. "Klubovna ..."
```

Souřadnice se dopočítají geokódováním zadané adresy, případně se adresa doplní zpětným geokódováním z bodu vybraného v mapě. Organizátor tak zadává místo jen jednou.

## Zvažované možnosti
* **A**: Adresa jako jeden textový atribut (`location: String`)
   * _Výhody_: nejjednoduší model i formulář.
   * _Nevýhody_: bez souřadnic nejde zobrazit mapu (F-02.2), nejde spolehlivě filtrovat podle města ani zobrazit čtvrť, geokódovat by se muselo při každém zobrazení.
* **B**: Adresa a souřadnice jako ploché atributy přimo v akci (`street`, `city`, ..., `latitude`, `longitude`)
   * _Výhody_: splní funkční požadavky, jednoduchá mapování do jedné tabulky.
   * _Nevýhody_: Akce se nafukuje o atributy, které spolu logicky souvisí; stejnou strukturu nejde znovu použít jinde (např. lokalita skupiny F-02.5 nebo profilu F-04.1); validace a konzistence adresy se souřadnicemi se rozptyluje.
* **C**: Lokace jako objekt v kompozici s akcí (**zvoleno**)
   * _Výhody_: místo je jeden soudružný celek s vlastní validací; strukturovaná adresa umožní filtrování, souřadnice mapu a hledání v okolí; typ lze znovu použít i jinde; v databázi lze stále uložit do sloupců tabulky akcí, takže nepřidává složitost.
   * _Nevýhody_: stejné místo se u opakovaných akcí ukládá opakovaně; oprava místa se nepropíše do jiných akcí.
* **D**: Místo jako samostatná entita s vlastním ID (vazba `Event` * -> 1 `Location`)
   * _Výhody_: opakovaně používaná místa (stálá klubovna, hřiště) jsou uložena jednou, dají se nabízet k výběru a mít vlastní detail.
   * _Nevýhody_: složitější model i formuláře, je třeba řešit vlastnictví místa, jeho úpravy a mazání, duplicity a sdílení mezi organizátory. Žádná funkce MVP to zatím nevyžaduje.

## Důsledky
* Snazší zobrazení akcí v mapě, hledání v okolí, filtrování podle města a zobrazení části adresy na kartě akce, protože data jsou strukturovaná a souřadnice uložené.
* Navazující práce: zapojit geokódování a našeptávač podle volby mapové služby (F-12.3) a ošetřit případ, kdy geokódování selže (např. organizátor upřesní pin ručně).
* Navazující práce: rozhodnout, jak zobrazit soukromé prostory na veřejné mapě, aby pin neprozradil přesnou adresu před schválením (F-02.4, F-10.4), např. přibližnými souřadnicemi nebo zobrazením jen čtvrti. Podle toho bude možná potřeba doplnit do Location atribut pro čtvrť (F-02.3).
* Otevřené: kam v modelu patří typ místa (veřejné / soukromé prostory, F-05.1), zda jako atribut Event, nebo Location.
* Riziko: pokud se ukáže, že se místa často opakují, bude potřeba přejít na možnost D. Přechod je proveditelný, protože struktura Location zůstane stejná, jen dostane vlastní identitu.
